# Implementation plan: project-01-interactive-login ("Aura")

Status: REVIEWED TWICE (revised after docs/plan-review.md and docs/plan-audit-2.md; APPROVED by Sajjad on 2026-11-12; faces = Unsplash, confirmed 2026-11-12)

Source of truth for motion: `reference/analysis.md` (timeline items #1 to #13). Where the second audit re-measured a value from the frames, this plan cites the frame and `motion.ts` uses the re-measured value (see audit-2 findings A1 and A4).

## 1. What will be built

A single-route Expo Router app that reproduces the reel end to end in Expo Go on the iOS Simulator:

1. **Intro (locked) state:** gradient + blue bottom glow + pulsing swipe handle.
2. **Interactive swipe-up:** live blurred preview of the welcome scene; cancel springs back; commit fires the soap-bubble lens reveal.
3. **Welcome scene:** headline, a continuous 3D soap-bubble stream with face photos and iridescent rims (near-camera bubbles go soft and fade before they leave), a cycling SEND/RECEIVE/SWAP label bubble, Sign in / Sign up pills, and touch-reactive bubbles.
4. **Create Your Aura card:** a container-transform morph from the tapped pill into a frosted card with a real phone `TextInput` (phone pad), keyboard-follow, back-chevron and swipe-down dismiss, and reverse collapse.

Out of scope: real auth, the email flow, any network calls. Target platform is iOS (Expo Go). Android is not a target for this reel: expo-blur on Android needs a `BlurTargetView` and would show a tinted view instead of the lens (see §10).

## 2. Architecture and folder structure

One feature, `src/features/aura-login/`. State is a single phase machine kept in shared values so every transition runs on the UI thread:

`phase: 'locked' | 'dragging' | 'revealing' | 'welcome' | 'sheetOpening' | 'sheet' | 'sheetClosing'`

React state changes only at phase boundaries (via `scheduleOnRN`) for things like `pointerEvents` and the label timer, never per frame. With the React Compiler on, shared values are read with `.get()` only inside worklets/animated hooks, never during render.

```
src/app/_layout.tsx                        (Orchestrator) font loading + <KeyboardProvider>
src/app/index.tsx                          (Orchestrator) re-exports AuraLoginScreen
src/features/aura-login/
  aura-login-screen.tsx                    composition, layer order, root gesture container
  state.ts                                 useAuraState(): typed shared-value contract
  motion.ts                                all measured durations/curves/thresholds (cites analysis # / frame)
  bubbles/
    bubble-sim.ts                          worklet particle sim (spawn, integrate, project, recycle, sort)
    bubble-canvas.tsx                      Skia <Canvas>; draws one depth layer of the sim (back or front)
    bubble-paint.ts                        worklet drawBubble(canvas, …): face shader, glass, rim, highlight, defocus
    use-bubble-images.ts                   loads faces with Skia useImage; builds the pre-blurred variants once
  components/
    background-gradient.ts                 welcome gradient paint, drawn first in the back canvas
    use-swipe-reveal.ts                    pan hook: p, thresholds, commit/cancel
    reveal-lens.tsx                        lens: fixed-size circle clip + BlurView, transform-animated; ends as the label bubble body
    lens-rim-canvas.tsx                    full-screen Skia canvas that strokes the iridescent rim at the lens radius
    card-morph.ts                          rect/radius lerp + dismiss-pan worklets
    intro-overlay.tsx                      intro gradient, blue glow, handle, caption (uses use-swipe-reveal)
    welcome-header.tsx                     WELCOME TO / mixed serif-italic headline / subtitle / back chevron
    label-bubble.tsx                       cycling label text + tap-to-advance (sits on the lens body)
    auth-buttons.tsx                       Sign in / Sign up pills; reports pill frames
    create-aura-card.tsx                   morphing frosted card + content + TextInput
    avatar-cluster.tsx, phone-field.tsx    card sub-parts
  assets/faces/*.jpg + CREDITS.md          12-16 licensed portraits (256 px), source pending Sajjad's choice
src/theme/colors.ts                        add the Aura tokens from analysis §3 alongside the existing ones
src/theme/typography.ts                    add the serif italic family
```

Render layer order (bottom → top):

1. **Back canvas** (Skia): welcome gradient + back-layer bubbles
2. Welcome RN layer: header (with the back chevron), pills, terms
3. **Front canvas** (Skia, `pointerEvents="none"`): front-layer bubbles
4. **Preview blur** (`expo-blur` BlurView at a fixed intensity of about 28, full screen, plus a dim View). Its own opacity is never animated (audit-2 A3). It is mounted in `locked`/`dragging` and removed the frame the lens reaches full size.
5. **Lens** (`reveal-lens.tsx`): a fixed-size `overflow:hidden` circle, diameter = 2 × screen diagonal, constant `borderRadius`, containing a BlurView and a dark tint View. Only `transform` (translate + scale) and the tint opacity animate (audit-2 A2). Its end state is the label bubble's glass body.
6. **Lens rim canvas** (full-screen Skia, `pointerEvents="none"`): one sweep-gradient stroke at the lens centre/radius.
7. Label text (`label-bubble.tsx`), centred on the emitter, legible above the blur as in the reference.
8. Intro overlay: intro gradient + blue glow + handle (opacity 1 − p).
9. Card morph layer.

The bubble-touch manual gesture is attached to the screen's root container (the parent of every layer), not to a sibling overlay, so hit-testing still reaches the pills (audit-2 B4).

Shared values live in `state.ts` (`useAuraState()`, Orchestrator): phase, p, lens scale/centre, lens tint, emitter centre, touch point/velocity, pill frames, frame tick, sim-active flag. Components receive them as typed props.

Bubble touch: a `useManualGesture` attached to the screen's root container that never activates (it only reads touches down/move), writes the touch point and velocity to shared values. Because it never activates it doesn't cancel the pills' or label's touches, and because it lives on the parent rather than a sibling overlay, hit-testing still reaches them. The sim applies a radial impulse to bubbles within 90 pt, which decays. Behind `motion.bubbleTouch.enabled`, because the reference is ambiguous (analysis §7).

Iridescence quality ladder (stop when it looks right):

1. `SweepGradient` stroke, 1.5 pt, 6 colour stops, rotated per bubble.
2. Add a second offset stroke with `BlendMode.Screen` and blur 1 for the soft film.
3. Optional SkSL `RuntimeEffect` thin-film shader, only if 1 and 2 look flat.

- Manual gesture matrix: slow drag/cancel, fast flick commit, drag back down mid-way, tap during reveal, tap a pill through a front-layer bubble, tap the label bubble, double-tap Sign in, dismiss during the opening morph, swipe-down dismiss (commit and cancel), reset via the back chevron (welcome → locked, for demo replay), open and close the card three times in a row (field still full on every close, pill reappears).

## 9. Performance risks

1. **56 image draws + gradient strokes per frame across two canvases:** keep each bubble to 1 image + 2 strokes (the defocus crossfade adds one image only for the few near-plane bubbles). One `ImageShader` paint per face, reused through canvas transforms. Fallback: lower N or drop the blur on the rim.
2. **Live BlurView over an animating field (preview and lens):** expensive on the simulator. The step 0 spike measures it. The fallback is a lower stream N during `dragging`/`revealing`.
3. **Animating layout props per frame:** width/height/left/top/borderRadius go through a shadow-tree commit every frame and resize the native blur view. The lens therefore animates only `transform`. The card morph uses layout props for 250 ms on one view; if the spike shows hitches, switch it to a fixed final-size clip view with transform + an inner rect mask.
4. **Sim data in a shared value:** mutate a preallocated array in place inside the frame callback, sort with a preallocated index array, and never allocate per frame. Pre-warm on the UI runtime.
5. **Blur view alpha:** never animate the opacity of a BlurView or of a view that contains one (UIKit doesn't support a visual-effect view under alpha < 1). Fade the layers above it, or animate `intensity` via `animatedProps`.
6. **Sim while the card is open:** the field is fully covered, so `setActive(false)` freezes the frame callback (no sim, no draw) and resumes it on close.

## 10. Known limitations

- The reference is filmed footage of a phone, so colours and sizes are estimates (±10%).
- Whether bubbles react to touch is not provable from the video. It is implemented as an optional, tunable behaviour.
- The face photos will differ from the creator's (licensed stand-ins; source still to be chosen by Sajjad).
- The system keyboard look comes from iOS and is not custom.
- The card's content fades/scales on collapse; in `d_*` it also looks blurred. A per-frame content blur is not planned (cost vs. a 300 ms effect).
- iOS only. On Android the preview, lens and card blur would need `BlurTargetView` + `blurMethod`, which is not planned.
