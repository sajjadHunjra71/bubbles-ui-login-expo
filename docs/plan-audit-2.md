# Plan audit 2: project-01-interactive-login

- **Auditor:** independent senior React Native architect / animation engineer (second pass, no part in the plan or the first review)
- **Inputs:** `docs/implementation-plan.md` (post-review version), `reference/analysis.md`, `reference/frames/` (contact sheets plus `dense-reveal/r_001..r_042`, `dense-sheet/s_*`, `d_*`), `docs/plan-review.md`, `package.json`, `node_modules`, Expo SDK 58 docs
- **Date:** 2026-11-12

## Verdict

**READY TO APPROVE after these fixes, which are already applied to the plan.** Nothing found needs a different architecture. The two most important changes: the lens shrink was timed about 40% too short, and the lens was animated through layout props on a blur view. One open item is still Sajjad's: the face-photo source (Unsplash portraits vs CC0 avatars). That blocks step 1 only, not the step 0 spike.

## What I verified

- `node_modules/expo/bundledNativeModules.json`: `@shopify/react-native-skia` 2.14.0 and `react-native-keyboard-controller` 1.22.7.
- Expo SDK 58 docs (`/versions/v58.0.0/sdk/skia/`, `/keyboard-controller/`, `/blur-view/`): both Skia and keyboard-controller are marked "Included in Expo Go". The BlurView `intensity` page says it can be animated with Reanimated. On Android a real blur needs `BlurTargetView`. `borderRadius` is not applied to BlurView directly, so the plan's `overflow:hidden` wrapper is still right.
- Reanimated 4.7.1 marks `useAnimatedKeyboard` `@deprecated` in favour of keyboard-controller.
- Frame measurements below come from `dense-reveal/r_001`, `r_011`, `r_021`, `r_033`, `r_042` (stacked side by side) and the 12 fps / 8 fps contact sheets. Each is normalised to the 393 pt screen width (±10%, as in the analysis).

## Checked and found sound

- Two Skia canvases with the depth layer fixed at spawn (about 22% front) matches the frames: bubbles cover the headline (`hero-3.6s.png`) and some pass behind "Sign in".
- `createPicture` + `<Picture>` keyed on a frame tick, a `Float32Array` mutated in place, and `useFrameCallback` on the UI thread are the right fit for 56 particles in Skia 2.x.
- A full-screen BlurView above both canvases for the drag preview (first-review finding 1) and an RN-clip lens with a real BlurView (finding 3) remain the right calls. The first review's other findings are still correctly reflected.
- Card morph #11/#13 durations match `s_009..s_024` / `d_009..d_027`. The card fully covers the field when open, which justifies freezing the sim.
- No dependency needs a dev build.
